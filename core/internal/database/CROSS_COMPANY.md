# Reads across companies

Every statement in core that reads more than one company's rows is listed
here with why, and carries the comment `-- cross-company: <reason>` so the
tenant check (tenant_test.go) lets it through. Each returns ids only, and the
work then continues through company-scoped functions with the row's own
company.

| Statement | File | Why |
|---|---|---|
| Claim the next due job | internal/jobs/store.go | Workers serve every company: the claim returns the job's id, company and kind; the job then runs with its own company. |
| Hand back jobs cut off while running | internal/jobs/store.go | A worker that died leaves its job "running": after its lease, the job is queued again (or failed past its tries). Ids only. |
| Find a Telegram account by its business connection id | internal/telegram/store.go | The id Telegram sends names the company; returns that company and account id only. |
| Claim a conversation whose "answer if I haven't within N minutes" is due | internal/assistant/catchup.go | The catch-up serves every company: the claim clears the due time and returns the company and conversation ids; the reply job then runs with that company. |
| Claim a Telegram link code by its hash; find the code a Telegram user claimed | internal/telegram/linkstore.go | The code ansa made names its company (only its hash is stored); returns that code's id, company and maker only. |
| Update the Telegram account a business connection id names; find which company an account is tied to | internal/telegram/linkstore.go, linking.go | Telegram's connection id names the one company a code tied it to; only that row (its company id) is read or changed. |
| Is a platform account still connected anywhere? (before a Disconnect has X or Google revoke) | internal/social/revoke.go | X's and Google's grant is the account's with ansa's one app, so a revoke would end every company's connection of it: yes or no only, never which company or anything of the rows; asked only after the disconnect answered. |
| Find the one company that has a Facebook Page connected (a Messenger message, or a comment on the Page's posts) | internal/messenger/store.go | The Page id Meta signed names the company, only when exactly one has it; returns the company and connection ids only (a comment is then saved and answered through core/internal/comments' company-scoped statements). |
| Find the one company that has a WhatsApp number connected | internal/whatsapp/store.go | The phone number id Meta signed names the company, only when exactly one has it connected; returns the company and number ids only. |
| Find a WhatsApp business account's numbers, when Meta ends or restores the link | internal/whatsapp/store.go | The business account id Meta signed names its numbers; returns the company and number ids only, and each status change is then written with the row's own company. |
| Find who a session cookie belongs to | internal/session/session.go | The session token names one person; returns their id, company, role, name and address, and only their own company is used after. |
| Find the company of a forwarding address's token | internal/resend/webhook.go | Only ansa makes forwarding addresses; the token names the company, only when exactly one matches; ids only. |
| Record a delivery problem on a sent email by Resend's id | internal/resend/webhook.go | Resend's id names one sent email of one company; only that row changes. |
| Claim the next due post | internal/publishing/claims.go | The publishing queue serves every company: one UPDATE claims one due job (a scalar SKIP LOCKED subquery) and returns its ids; the post then runs with its own company. |
| Find posts cut off while sending | internal/publishing/handover.go | Still "publishing" 10+ minutes after their claim, of every company; ids only, each handed to a person through the company-scoped path. |
| List the companies with "Post for me" on | internal/autopost/store.go | The runs serve every company that has it on: ids and their posting settings only; each post is then written through company-scoped paths. |
| Find stuck image and video requests | internal/mediagen/stuck.go | The periodic task serves every company: requests waiting 2+ minutes or cut off 15+ minutes ago (the old db/stuck-work.ts); ids only, each then claimed and run through the company-scoped path. |
| Claim the next post due for its numbers | internal/postmetrics/collector.go | The collector serves every company: one UPDATE claims one published post (a scalar SKIP LOCKED subquery) and returns its ids; the read then runs with its own company. |
| Delete expired connection attempts, used-up Telegram link codes, finished jobs past 30 days | internal/maintenance/cleanup.go | Housekeeping by age alone: nobody can use such a row any more; nothing is read. |
| Find an account by its address (login, confirming) | internal/accounts/login.go | An address belongs to one account across companies (users.email is unique); only that person's own row and password are read. |
| Check, preview and claim an invite by its token's hash | internal/accounts/signup.go | Only ansa makes invite tokens (only their hash is stored); the token names its company; only that invite's row (and its company's name for the preview) is read or changed. |
| Find the company of a Stripe customer | internal/billing/billing.go | Only after Stripe's signature checked out: a Stripe customer belongs to one company; only its id is read, and billing never moves between companies. |
| Find the company of a Vapi phone line (an ended call, a live knowledge search) | internal/calls/webhook.go, internal/calls/tools.go | Only after Vapi's signature checked out: only ansa's operator links phone lines, and a Vapi number id belongs to one company (unique); only the line's id and company are read, never anything the payload says about a company. |
| Find the post a simulation names by its id | internal/analytics/simulate.go | `go run ./cmd/simulate post-metrics` (development and a database on this computer only, as the old `pnpm simulate:post-metrics`): a command run by hand has no session; it reads one post's company, status, platform and whether its account is the stand-in, by an id nobody can guess, and writes only through the company-scoped save. |
| Find the demo accounts by their fixed addresses and domain (`demo`, development only) | cmd/simulate/demo.go | The demo tool deletes and makes again only accounts on its own address domain (`business@demo.ansa.test`, `rafa@demo.ansa.test`, the teammate it adds and anyone a rehearsal signed up on `@demo.ansa.test`), on a development server with a database on this computer (the tool's guard): it reads their user and company ids, and everything after goes through company-scoped statements. |
| Find a company by its owner's address (every operator command and development tool) | internal/commands/commands.go | A command run by hand has no session: the person running it types an address, and only a confirmed, active OWNER's finds a company (an invited or unconfirmed account may sit in the wrong company). An address is one account (users.email is unique); returns that company's id and name and the owner's id only, and everything after goes through company-scoped statements. A company id is never typed in. |
| Is a Vapi number linked already, to this company or another? (`link-phone-line`) | internal/commands/phonelines.go | Only ansa's operator links numbers, and a number belongs to one company (unique): yes or no, and whether it is the found company's; never which other company or anything of its rows. The link itself is a company-scoped INSERT. |
